# 2. Процессы AS-IS и TO-BE

[← К оглавлению](../README.md)

Диаграммы построены по логике BPMN (участники, события, задачи, шлюзы) и записаны в Mermaid, чтобы GitHub отображал их прямо на странице. Обе схемы идут сверху вниз, а участник показан цветом блока. Легенда в верхней строке каждой схемы.

## AS-IS: запись по телефону

```mermaid
%%{init: {"flowchart": {"rankSpacing": 28, "nodeSpacing": 30, "wrappingWidth": 320}}}%%
flowchart TB
    subgraph L[" "]
        direction LR
        L1[Пациент]:::patient ~~~ L2[Администратор]:::admin ~~~ L3[МИС]:::mis
    end
    L ~~~ P1

    P1([Нужен приём]):::patient
    P2[Звонит в клинику]:::patient
    A1{Линия свободна?}:::admin
    A2[Отвечает на звонок]:::admin
    P3[Называет врача и удобное время]:::patient
    A3[Ищет свободные слоты в МИС]:::admin
    M1[Показывает расписание врача]:::mis
    A4{Есть подходящее время?}:::admin
    A5[Вносит запись в МИС вручную]:::admin
    M2[Сохраняет запись]:::mis
    P4([Записан]):::patient
    P5([Отказался от записи]):::patient
    A6[За день до приёма звонит пациенту с напоминанием]:::admin
    P6{Пациент пришёл?}:::patient
    P7([Приём состоялся]):::patient
    P8([Неявка: время врача потеряно]):::patient

    P1 --> P2 --> A1
    A1 -- "Нет, 18% звонков" --> P5
    A1 -- Да --> A2 --> P3 --> A3 --> M1 --> A4
    A4 -- Нет --> P5
    A4 -- Да --> A5 --> M2 --> P4
    P4 -.-> A6 --> P6
    P6 -- Да --> P7
    P6 -- "Нет, 14% записей" --> P8

    classDef patient fill:#dbeafe,stroke:#2563eb,color:#0b1b3a
    classDef admin fill:#fef3c7,stroke:#d97706,color:#3b2405
    classDef mis fill:#f1f5f9,stroke:#64748b,color:#0f172a
    style L fill:none,stroke:none
```

### Узкие места AS-IS

| # | Где | Что не так |
|---|---|---|
| 1 | «Линия свободна?» | Единственный канал записи, в часы пик пациент не может дозвониться |
| 2 | «Ищет свободные слоты» | Администратор подбирает время, пока пациент ждёт на линии |
| 3 | «Вносит запись вручную» | Риск ошибки: не тот врач, не то время |
| 4 | «Звонит с напоминанием» | Ручной труд, до части пациентов не дозвониться, отменённые слоты не освобождаются заранее |
| 5 | Вне рабочего времени | Процесс недоступен совсем |

## TO-BE: онлайн-запись

Как запись будет работать после внедрения. По этой схеме согласуем процесс с клиникой до того, как писать требования: из шагов пациента получаются user stories, из шагов сервиса — функциональные требования.

```mermaid
%%{init: {"flowchart": {"rankSpacing": 28, "nodeSpacing": 30, "wrappingWidth": 320}}}%%
flowchart TB
    subgraph L[" "]
        direction LR
        L1[Пациент]:::patient ~~~ L2[Сервис онлайн-записи]:::service ~~~ L3[МИС]:::mis
    end
    L ~~~ P1

    P1([Нужен приём]):::patient
    P2[Выбирает филиал, специальность и врача]:::patient
    S1[Запрашивает свободные слоты]:::service
    M1[Отдаёт расписание врача]:::mis
    S2[Показывает свободные слоты]:::service
    P3[Выбирает время]:::patient
    P4[Вводит телефон и код из SMS]:::patient
    S3{Слот ещё свободен?}:::service
    M2[Сохраняет запись]:::mis
    S4[Отправляет SMS-подтверждение]:::service
    P5([Записан]):::patient
    S5[Отправляет напоминания за 24 ч и за 2 ч]:::service
    P6{Планы изменились?}:::patient
    P7[Отменяет или переносит запись в личном кабинете]:::patient
    P8([Приходит на приём]):::patient
    S6[Передаёт отмену или перенос в МИС]:::service
    M3[Освобождает слот для других пациентов]:::mis

    P1 --> P2 --> S1 --> M1 --> S2 --> P3 --> P4 --> S3
    S3 -- "Нет, слот заняли" --> S2
    S3 -- Да --> M2 --> S4 --> P5
    P5 -.-> S5 --> P6
    P6 -- Нет --> P8
    P6 -- Да --> P7 --> S6 --> M3

    classDef patient fill:#dbeafe,stroke:#2563eb,color:#0b1b3a
    classDef service fill:#dcfce7,stroke:#16a34a,color:#052e16
    classDef mis fill:#f1f5f9,stroke:#64748b,color:#0f172a
    style L fill:none,stroke:none
```

### Что изменилось

| Было (AS-IS) | Стало (TO-BE) | Какую проблему решает |
|---|---|---|
| Запись только по телефону в рабочие часы | Онлайн 24/7, телефон остаётся как запасной канал | P1, P5 |
| Администратор ищет слот при пациенте | Пациент сам видит свободные слоты | P2, P4 |
| Ручной ввод в МИС | Запись создаётся в МИС через API | P2 |
| Ручной обзвон | Автоматические SMS за 24 ч и за 2 ч со ссылкой на отмену | P3, P4 |
| Отменённый слот теряется | Отмена сразу освобождает слот для других | P3 |

## Процесс напоминания и отмены (подробно)

```mermaid
sequenceDiagram
    autonumber
    participant S as Сервис записи
    participant SMS as SMS-провайдер
    actor P as Пациент
    participant MIS as МИС

    S->>SMS: Напоминание за 24 ч (дата, врач, адрес, ссылка)
    SMS->>P: SMS
    alt Пациент отменяет
        P->>S: Переход по ссылке → «Отменить запись»
        S->>MIS: POST /appointments/{id}/cancel
        MIS-->>S: 200 OK
        S->>SMS: Подтверждение отмены
        SMS->>P: «Запись отменена»
    else Пациент ничего не делает
        S->>SMS: Напоминание за 2 ч
        SMS->>P: SMS
    end
```
